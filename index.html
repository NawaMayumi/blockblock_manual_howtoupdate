01

まず知っておく3つの言葉

これさえ分かれば、あとは全部この3つの組み合わせです。

ターミナル

文字を打ち込んでコンピュータに直接指示を出すための画面です。ふだんのアプリのようなボタンやメニューはなく、命令文を1行ずつ打って実行します。Claude Codeは、このターミナルの中で動くプログラムです。Macなら最初から入っている「ターミナル」というアプリを開くだけで使えます。

GitHub / リポジトリ

たとえるなら「プロジェクトの共有ロッカー + 変更履歴の記録帳」です。ファイル一式(=リポジトリ)を保管し、「いつ・誰が・何を変えたか」を全部記録してくれます。BlockBlockは github.com/NawaMayumi/blockblock というリポジトリに置かれています。

commit / push

commitは「この変更をひとまとまりの記録として残す」こと、pushはその記録を実際にGitHub(共有ロッカー)へ送って反映させることです。push して初めて、みんなが見られる状態(公開サイトも含む)に変更が届きます。

02

なぜGoogle Apps Scriptではないのか

「Google Workspaceが使えるなら、それで作れないの?」という疑問への答えです。

結論から言うと、Google Apps Script(GAS)ではこのアプリは作れません。理由はGASの得意・不得意ではなく、もっと単純な制約です。

GASで作るWebアプリは、Google側が用意する「サンドボックス化されたiframe」という枠の中に読み込まれます。ブラウザのカメラ機能は、その枠にcameraという許可が明示的に与えられていないと使えない仕組みになっており、GASのiframeにはその許可を与える方法がありません。BlockBlockの心臓部は「カメラでブロックを認識すること」なので、この時点で選択肢から外れます。

一方、今の方式(ただのHTML・CSS・JSファイルをGitHub Pagesで配る)は、ページがiframeに包まれずブラウザで直接開かれるため、カメラの許可ダイアログも普通に出ます。遠回りに見えて、実はこれが一番シンプルに動く方法でした。

03

実際の直し方

Claude Codeに頼んで、変更を公開サイトまで届ける一連の流れです。

ターミナルを開く

Macなら「ターミナル」アプリを開きます(Spotlight検索で「ターミナル」と打てば見つかります)。

claude と打ってEnter

Claude Codeが起動し、会話できる状態になります。

日本語で、直したいことを伝える

「どこの」「何を」「どうしたいか」を具体的に書くほど正確に伝わります。

左上のスコア表示が見づらいので、もっと大きくしてください

提案された変更を確認する

Claude Codeがファイルを編集しますが、実際にはあなたが確認して承認するまで確定しません。変更内容(どこがどう変わるか)を見せてくるので、目を通してから進めます。

「pushして」「公開サイトに反映して」と伝える

Claude Codeがcommit・pushまで行います。

これでpushして、公開サイトに反映してください

数十秒待って、公開URLを確認する

GitHub Actions(自動処理の仕組み)が自動的にGitHub Pagesへ反映するよう設定済みなので、手動での「公開」操作は不要です。nawamayumi.github.io/blockblock を開き直して確認します。

04

気をつけること

今の運用体制だからこそ、意識しておきたい点です。

  • 今は誰でも main(本番)ブランチに直接pushできる状態です。複数人で触るようになったら、「pushする前に別の人が確認する」というレビューの仕組み(Pull Request)を検討してください。
  • 大きく作り変える前は、今の状態を一度pushしておく(区切りをつけておく)と、うまくいかなかったときに戻しやすくなります。Claude Codeに頼めば基本的にやってくれます。
  • 思っていたのと違う変更になった・分からなくなったときは、遠慮なく「さっきの変更を元に戻して」と伝えてください。
  • コードの中身(なぜそう動くか)を詳しく知りたいときは、「BlockBlock 引き継ぎノート」の該当箇所を先に読んでからClaude Codeに質問すると話が早いです。
迷ったら

「これで合っているか分からない」まま進めるより、Claude Codeに「今何をしようとしているか」「何が不安か」をそのまま伝えてしまうのが一番早い解決策です。日本語での説明を理解して、次にすべきことを提案してくれます。
